# Weekly Review

Ten to fifteen minutes a week. This is how the system keeps getting smarter
without getting messier. Nothing changes until the owner says OK.

## Steps
1. **Gather the week.** Look at what changed in the folder over the last seven
   days and any session history your tool can read. Ask the owner: "Anything
   this week where I got it wrong, or where you had to explain the same thing
   twice?"
2. **Check five things:**
   - **Lessons:** corrections the owner made that aren't written down yet.
     Route each with the rules in `AGENTS.md`.
   - **Skill ideas:** any task done two or more times this week without a
     skill. Name it and say what it would save.
   - **Skills that missed:** results the owner rewrote or rejected. Find the
     line in the skill to fix.
   - **Stale facts:** "as of" dates older than about 90 days on prices, crew,
     status, priorities, or numbers. List them for the owner to confirm.
   - **Clean-up:** loose files at the top level or in `inbox/`, the same rule
     written in two places, connections in `working-style.md` that stopped
     working, finished one-offs in `active/`.
3. **Report on one screen:**
   - Top three fixes, ranked by time saved.
   - Everything else as a short checklist.
   - For each: the exact change and the file it goes in.
4. **Apply what the owner approves,** one file at a time. Read each back.
5. **Close with one line:** what got better this week and the one thing to
   watch next week, including how the constraint is trending.

## Rules
- Suggest, don't decide. The owner approves every change.
- Don't add to `MEMORY.md` unless it clears the bar written in that
  file.
- Don't move or delete files without the owner's OK.
- If the week was quiet, say so and stop.
